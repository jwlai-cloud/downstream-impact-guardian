Downstream Impact Guardian

A PR-triggered agent that reads DataHub for the real cross-team blast radius of a dbt change, proposes a Data Contract back into the catalog, and posts mergeable compatibility code — inside the GitHub Action runner. The PR looks fine. DataHub knows better.

The problem: a team upstream changes one field. Nothing errors, so nobody notices the assumptions your models rest on just broke — until the board reads wrong revenue. Detecting the change is easy; knowing who depends on it lives in the catalog, not the code.

Why it's trustworthy

Deterministic core

  • severity, verdicts, generated SQL and the contract are pure functions of the detected facts
  • the LLM narrates and cross-checks — it never scores, never authors merged code

Honest by construction

  • DataHub only reflects reality — the PR's state is never ingested
  • advisory, never blocking — stakeholders are informed early, before merge
